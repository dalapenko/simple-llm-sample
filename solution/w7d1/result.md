# W7D1 — Developer Assistant: Отчёт

## Что реализовано

### Developer Assistant Mode

Режим ассистента разработчика превращает LLM Chat CLI из универсального чат-бота
в инструмент, осведомлённый о конкретном проекте. Он работает на трёх уровнях:

1. **RAG по документации проекта** — система индексирует README, `project/docs/`
   и любые другие документы командой `/index <путь>`. После этого каждый вопрос
   автоматически обогащается релевантными фрагментами документации.

2. **MCP Git-сервер** — новый модуль `mcp-server-git` подключается как внешний
   инструмент и предоставляет агенту доступ к состоянию репозитория:
   текущая ветка, статус файлов, diff, история коммитов.

3. **Умная команда `/help`** — при активном RAG вместо статичного списка команд
   вызывается LLM, который получает контекст из документации и git-состояния
   и возвращает осмысленный обзор проекта.

## Плюсы взаимодействия с LLM-агентом для навигации по проекту

**Контекстные ответы.** LLM не просто ищет ключевые слова — он понимает вопрос
и синтезирует ответ из нескольких источников одновременно (docs + git + история).

**Снижение когнитивной нагрузки.** Разработчику не нужно читать всю документацию —
достаточно спросить на естественном языке. Особенно ценно при онбординге в незнакомый проект.

**Актуальность через инструменты.** Git MCP-сервер даёт агенту доступ к живому
состоянию репозитория — ответы про текущую ветку или последние изменения всегда актуальны.

**Объяснение архитектуры.** Агент способен объяснить не только «что», но и «почему»,
если документация описывает принятые решения.

## Минусы и ограничения

**Зависимость от качества документации.** Если docs устарели или написаны небрежно,
агент будет давать неточные ответы. RAG усиливает как хорошую, так и плохую документацию.

**Латентность.** Каждый `/help` — это запрос к LLM (1–3 секунды). При медленном
провайдере или большом контексте пауза заметна.

**Галлюцинации при низкой релевантности.** Если вопрос не покрыт документацией,
агент может ответить правдоподобно, но неверно. Порог релевантности (0.35) снижает,
но не устраняет этот риск.

**Стоимость токенов.** Каждый RAG-запрос увеличивает контекст на несколько тысяч
токенов. При использовании облачных моделей это влияет на стоимость.

**Инерция базы знаний.** После изменения документации нужно заново запускать `/index`.
Автоматической синхронизации нет.

## Демонстрация

В `demo.gif` показано:
- Запуск CLI с `--rag advanced` и подключение Git MCP-сервера
- Индексирование `project/docs/` (3 файла, 31 чанк)
- `/help` → LLM вызывает `git_branch` и `git_status`, возвращает обзор проекта
- Вопрос о текущей git-ветке → агент вызывает инструмент и отвечает
- Вопрос о RAG-архитектуре → ответ на основе проиндексированной документации
