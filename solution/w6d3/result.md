# W6D3 — Локальный RAG vs Удалённый RAG: сравнение провайдеров

---

## 1. Зачем это нужно

RAG-система позволяет задавать вопросы по конкретным документам — коду, документации, заметкам. До этого момента и индексирование документов, и сам поиск работали только через OpenRouter: облачный сервис требовал API-ключа и интернета.

Теперь весь цикл работает локально — без ключей и без отправки данных куда-либо.

---

## 2. Сравнение: локальный vs удалённый RAG

### Демо

`solution/w6d3/demo.gif` — одни и те же три вопроса, заданных сначала через OpenRouter, затем через Ollama. Факты в ответах совпадают, стиль — разный.

### Плюсы локального RAG

- **Конфиденциальность** — документы, которые вы индексируете (код, внутренние инструкции, личные заметки), не покидают ваш компьютер ни на секунду. При работе с облаком каждый запрос и каждый найденный фрагмент отправляются на внешний сервер.
- **Без API-ключа** — можно развернуть и использовать без регистрации и оплаты. Удобно для команд, которые не хотят заводить общий ключ, или для экспериментов.
- **Работает оффлайн** — индексирование и поиск работают без интернета. Полезно в корпоративных сетях с ограниченным доступом наружу или просто в дороге.
- **Предсказуемая стоимость** — нет платы за токены. При большом объёме документов или частых запросах это существенная экономия.

### Минусы локального RAG

- **Качество ответов ниже** — небольшие модели вроде `llama3.2` (2 ГБ) заметно уступают GPT-4o или Gemini: более короткие ответы, меньше деталей, иногда упрощения. Хорошие локальные модели (`phi4`, `qwen2.5:72b`) требуют мощного железа.
- **Скорость медленнее** — на обычном MacBook генерация токенов занимает дольше, чем у облачного API. Чем больше модель, тем заметнее разрыв.
- **Размерность векторов другая** — `nomic-embed-text` создаёт векторы размером 768, а `text-embedding-3-small` — 1536. База, проиндексированная одной моделью, несовместима с другой: при смене провайдера нужно переиндексировать.
- **Нужен подходящий компьютер** — для комфортной работы желательно от 16 ГБ RAM и Apple Silicon или NVIDIA GPU. На слабом железе скорость становится неприемлемой.

### Когда что выбирать

| Ситуация                                         | Рекомендация |
|--------------------------------------------------|--------------|
| Личные заметки, рабочий код, NDA-документы       | Локальный    |
| Нет интернета или корпоративный файрвол          | Локальный    |
| Нужен лучший результат, данные не чувствительные | Удалённый    |
| Прототип или быстрая проверка идеи               | Удалённый    |

## 3. Как запустить

### Подготовить Ollama

```bash
# Установить
brew install ollama

# Скачать модели
ollama pull llama3.2             # чат, ~2 ГБ
ollama pull nomic-embed-text     # эмбеддинги, ~274 МБ

# Запустить сервер
ollama serve
```

### Проиндексировать документы локально

```bash
./gradlew :cli-app:run --console=plain \
  --args="--provider ollama --local-model llama3.2 --mode basic"

# В чате:
# You > /index путь/к/документам structural
```

### Запустить с удалённым провайдером для сравнения

```bash
export OPENROUTER_API_KEY=...

./gradlew :cli-app:run --console=plain \
  --args="--provider openrouter --mode basic"

# You > /index путь/к/документам structural
```

## 4. Важные детали

- **Модели для эмбеддингов и чата независимы** — можно использовать `nomic-embed-text` для индексирования и любую другую Ollama-модель для ответов.
- **База несовместима между провайдерами** — если проиндексировали через OpenRouter, для локального RAG нужно переиндексировать через `--embedding-model nomic-embed-text`.
- **Качество поиска** — при одинаковых вопросах оба провайдера находят правильные фрагменты. Разница в том, как модель формулирует ответ по найденному контексту.
- **Guardrails работают одинаково** — защита от галлюцинаций («Я не знаю») срабатывает при низком косинусном сходстве независимо от провайдера.
